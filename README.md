# CyanCut

**가장 효율적이고 간결한 영상편집.** 가입 없이 브라우저에서 원본을 불러와 편집하고 실제 파일을 다운로드하는 로컬 영상 편집기입니다. React + TypeScript + Vite의 정적 앱이며 미디어 업로드 서버나 계정 서버가 없습니다.

배포 사이트: [cutandcut.vercel.app](https://cutandcut.vercel.app)

## 실행

Node.js 22.12+ 또는 24, npm을 사용합니다.

```sh
npm ci
npm run dev
```

터미널에 표시된 주소를 열어주세요. 기본 포트는 5173이며 사용 중이면 다음 포트로 변경됩니다. WebCodecs 때문에 HTTPS 또는 localhost가 필요합니다.

```sh
npm test
npm run build
npm run preview
```

실제 파일을 생성하고 편집·출력·복구하는 Chrome 통합 테스트:

```sh
# 별도 터미널에서 고정 포트로 실행
npm run dev -- --port 5174 --strictPort
npm run test:e2e
```

테스트는 설치된 Google Chrome을 사용합니다. `TEST_URL`로 서버 주소, `TEST_CHANNEL=msedge`로 Edge를 지정할 수 있습니다. macOS/Linux에서는 환경 변수 앞에 값을 붙이고, PowerShell에서는 `$env:TEST_URL='http://localhost:5174'`처럼 설정합니다. 실제 출력과 검증 JSON·스크린샷은 `artifacts/`에 생성되며 저장소에 커밋하지 않습니다.

## 편집 경로

### 휴대전화·태블릿 화면

프로젝트 메뉴 → **앱 설정 · UI 모드 → 모바일 모드**에서 전환합니다. 기본 모드는 기존 배치를 유지하며, 화면 선택은 기기에 저장되고 프로젝트·화면비·undo 기록을 바꾸지 않습니다. 모바일 상단 설정 버튼으로 되돌릴 수 있습니다.

모바일은 미리보기·타임라인과 하단 **미디어 / 텍스트 / 속성 / 화면 / 더보기**를 사용합니다. 클립을 탭해 선택하고, 선택한 클립을 끌어 이동하거나 양끝으로 트리밍합니다. 선택하지 않은 클립에서는 손가락으로 타임라인을 탐색합니다. 다중 선택을 켜서 여러 클립을 탭하고, 끈 뒤 함께 이동합니다. 정밀 시간·속성은 숫자 입력, 프레임 버튼과 더보기의 기존 정밀 도구로 조절합니다. 트랙 머리를 탭하면 잠금·음소거·순서·삭제 설정을 엽니다.

휴대전화는 아래 패널, 넓은 태블릿은 옆 패널, 가로 화면은 미리보기와 편집 영역을 나란히 배치합니다. 추가·속성 패널에서도 미리보기와 탐색을 유지합니다. 낮은 휴대전화 화면에서는 패널을 여는 동안 타임라인을 접어 영상 공간을 확보합니다. 키보드로 보이는 영역이 아주 낮아지면 입력 패널을 우선하고 타임라인·재생 조작은 패널을 닫아 다시 표시합니다. 상세 구성·검증·실기기 미검증 범위는 [MOBILE_UI.md](docs/MOBILE_UI.md)에 기록합니다. 이 모드는 기존 편집·출력 엔진을 공유하며 모바일 코덱 지원이나 대용량 성능을 별도로 보장하지 않습니다.

1. 여러 영상·이미지·음악을 선택하거나 화면에 끌어놓습니다. 기본은 **보관함에만 가져오기**입니다. 배치 선택 후 '선택한 미디어 추가'로 영상을 연속 삽입하거나, '가져오면서 타임라인에 연속 배치'를 켭니다. 이미지·음악은 재생헤드에 추가되고 겹치는 이미지·텍스트는 별도 시각 레이어에 배치됩니다. 분석은 취소할 수 있고, 오류 목록에서 파일별 원인·재시도를 확인합니다.
2. 보관함의 + 버튼 또는 트랙으로 드래그해 같은 원본을 다시 사용할 수 있습니다. 영상과 원본 오디오는 별도 트랙의 링크된 클립입니다. 영상 클립을 위 시각 트랙으로 수직 이동하여 겹칠 수 있으며 위쪽 레이어가 먼저 보입니다. 연결 오디오는 원래 오디오 트랙에 남고 시간 이동은 함께 적용됩니다. 드롭 위치를 미리 표시하며 잠긴 트랙·호환되지 않는 트랙은 이유를 알리고 이동을 취소합니다.
3. 재생헤드를 옮겨 분할하고 클립 양끝을 드래그해 트리밍합니다. 시작·길이·원본 시작은 속성 패널에서도 조절할 수 있습니다. 비파괴 편집이며 원본 파일은 변경하지 않습니다.
4. Shift/Ctrl/Cmd 클릭 또는 빈 트랙에서 마우스로 박스를 그려 여러 클립을 선택하고 함께 이동합니다. 그룹화·해제와 앞/뒤 클립 교환도 제공합니다. 겹친 클립은 속성 패널 목록이나 Tab → Enter로 선택합니다. 링크 또는 그룹에 잠긴 트랙이 있으면 부분 수정하지 않습니다.
5. 텍스트·전환 도구에서 추가하고 오른쪽 속성으로 스타일·오디오 페이드·볼륨을 설정합니다. 텍스트 내용은 입력 후 포커스를 벗어나면 한 undo 단위로 적용됩니다. 한글 IME 조합 중 단축키를 차단합니다.
6. 새 프로젝트는 **1080p·30FPS**로 시작합니다. 기존 저장 프로젝트의 해상도는 유지하며 720p도 선택할 수 있습니다. 선택을 해제하면 프로젝트 화면비·해상도·FPS·배경을 변경할 수 있습니다. 내보내기는 편집 모델의 독립 스냅샷을 사용합니다. 실제 환경에서 가능한 출력만 활성화하며 완료 후 플레이어로 확인하고 다운로드합니다.

타임코드에 `HH:MM:SS:FF`, `분:초` 또는 초 숫자를 입력하여 프레임 격자로 이동합니다. 이전/다음 경계, 재생헤드 앞/뒤 트림, 빈 구간 제거, I/O 지정·구간 재생·구간 출력을 제공합니다. 빈 구간 제거는 적용 전에 전체 트랙에서 잘릴 구간·클립과 이동할 클립을 보여주며, 확인 후 한 번의 undo로 적용합니다. 영향을 받는 잠긴 트랙이 있으면 거절합니다.

자막 탭에서 내용·시작·끝을 목록으로 편집하고 SRT/VTT를 가져오거나 저장합니다 (2MB·10,000개·1시간 이하). 제목·장식과 자막의 역할을 구분하고, 기본은 자막만 출력합니다. 선택 텍스트 또는 제목을 포함한 전체 출력도 선택할 수 있습니다. 이전 프로젝트의 미분류 텍스트는 역할을 지정하거나 전체 출력을 선택하세요. 선택 자막의 스타일을 잠기지 않은 텍스트 클립 전체에 적용할 수 있습니다. 스타일 정보는 SRT/VTT에 포함되지 않습니다.

클립 속도 0.5–2배와 음정 유지, 현재 합성 화면의 정지 PNG·5초 이미지 클립, 미리보기에서 위치·크기·크롭 조절, 반전·중앙 정렬·10% 안전 영역을 제공합니다. 회전한 클립은 숫자 속성으로 크롭합니다. 100/50/25% 미리보기 품질은 결과 해상도를 바꾸지 않으며 프록시 파일을 만드는 기능은 아닙니다. 안전 영역·선택 핸들은 출력에 포함되지 않습니다.

실시간 피크 미터와 트랙 단독 재생을 제공하며 프로젝트 메뉴에서 전체 믹스를 검사하고 피크 정규화합니다. 전체 볼륨은 최대 400%로 제한하고 undo·초기화가 가능합니다. 이는 LUFS 기반 음량 정규화가 아닙니다. 출력 완료 시 실제 클리핑 샘플을 안내합니다. 배속 미리보기는 브라우저의 음정 유지, 출력은 WSOLA를 사용하므로 정밀한 위상·파형까지 같다는 보장은 없습니다.

단축키는 현재 기능에 대응하는 Shotcut 체계를 사용합니다. **S 분할, X 리플 삭제, Z/Delete 일반 삭제**, C 또는 Ctrl/Cmd+C 복사, Ctrl/Cmd+X 잘라내기, V 또는 Ctrl/Cmd+V 삽입, A 끝에 추가, B 덮어쓰기, R 선택 교체를 제공합니다. 복사·붙여넣기 버튼과 방식 메뉴도 있습니다. Ctrl/Cmd+D는 선택 해제, 복제는 Ctrl/Cmd+Shift+D, 스냅은 Ctrl/Cmd+P로 변경했습니다. 한글 자판에서도 물리 키를 인식하며 입력·IME 조합 중에는 편집 키를 차단합니다.

타임라인 포커스에서 ↑/↓는 활성 트랙을 바꾸며 Alt+←/→로 클립 경계를 탐색합니다. I/O는 타임라인에서 앞·뒤 트림, 미리보기에서는 구간 시작·끝입니다. 구간 버튼은 항상 구간을 지정합니다. Shift+S는 재생헤드의 전체 트랙 분할이며 잠금으로 동기화를 보장할 수 없으면 거절합니다. Home/End는 프로젝트 시작·실제 끝으로 이동하고 Page Up/Down, 확대/축소·0 전체 보기, 트랙 추가·삭제·잠금·숨김·음소거, 선택 이동도 지원합니다. `?` 또는 `/` 도움말에서 키와 적용 범위를 확인하세요.

복사 버퍼는 현재 프로젝트 내부에 있으며 전환 시 초기화합니다. **자막·텍스트만 복사한 경우 V / Ctrl/Cmd+V / 붙여넣기 버튼은 기존 영상·오디오를 자르거나 이동하지 않습니다.** 한 텍스트 트랙의 복사본은 재생헤드에서 비어 있는 시각 레이어를 사용하고, 겹치면 새 레이어를 만듭니다. 여러 텍스트 트랙의 복사본은 원래 트랙과 상대 시간을 유지합니다. **영상·오디오가 포함된 삽입은 전체 트랙을 같은 길이만큼 밀고**, 교차 클립을 분할해 연결 동기화를 유지합니다. 미디어 단일 트랙 복사는 활성 호환 트랙에, 여러 트랙 복사는 원래 트랙에 배치하고 삭제된 원래 트랙은 새로 만듭니다. 덮어쓰기는 대상 트랙과 연결·그룹의 관련 구간을 잘라내며 나머지 시간은 이동하지 않습니다. 선택 교체는 선택과 연결·그룹 클립을 제거한 자리에 복사본을 놓습니다. 잠금·한 프레임 미만 경계·프로젝트 제한 때문에 불가능하면 기존 편집을 보존하고 이유를 안내합니다. 역방향 J는 소리 없는 프레임 탐색이고 프레임 이동은 재생을 정지합니다.

Shotcut의 필터·키프레임·마커·프록시·작업 목록·리플 모드 토글과 고급 리플 트림은 제공하지 않습니다. Ctrl/Cmd+N·W·Q·T 등 브라우저가 점유하는 키는 그대로 두며 프로젝트 메뉴를 사용합니다. 기기·브라우저에 따라 다른 키도 점유될 수 있으므로 버튼 대안을 제공합니다. 공식 기준과 차이, 재현·검증은 [docs/SHORTCUTS_FIX.md](docs/SHORTCUTS_FIX.md)에 있습니다.

## 현재 지원과 검증

전체 구조 리팩터링에서 트랙 활성화·오디오 인코딩·이름 입력·오류 정리를 공통화하고 잠금, 빠른 드래그, 장면 전환 캐시와 프로젝트 검증의 재현된 결함을 수정했습니다. 기능과 화면 구성은 유지합니다. 우선순위·위험도·보류 판단과 검증 범위는 [docs/REFACTOR_PASS.md](docs/REFACTOR_PASS.md)에 기록했습니다.

UX/UI polish에서 가져온 뒤의 다음 행동, 모바일 저장 상태·주요 버튼 배치, 메뉴와 출력 대화상자의 키보드 포커스, 로딩·오류·완료 안내를 정리했습니다. 편집/출력 기능과 프로젝트 규칙은 유지합니다. 코드별 문제·영향·변경 위험도와 화면 근거는 [docs/UI_POLISH.md](docs/UI_POLISH.md)에 기록했습니다.

아래는 **실제 파일로 확인한 조합**입니다. 확장자를 기준으로 내부 코덱까지 지원한다고 추정하지 않습니다. 파일마다 실제 컨테이너·트랙·코덱을 분석하고 브라우저의 디코더를 검사합니다.

| 입력 | 내부 형식             | 검증 범위                                                               |
| ---- | --------------------- | ----------------------------------------------------------------------- |
| MP4  | H.264/AVC + AAC       | 두 영상 가져오기·링크 편집·썸네일·합성·출력, 가변 PTS 영상의 24fps 출력 |
| PNG  | 정지 이미지·알파 채널 | 투명 영역·이동·크기·상위 레이어 합성                                    |
| JPEG | 정지 이미지           | 가져오기·1080p 합성 출력                                                |
| WAV  | PCM 16-bit            | 파형·볼륨·페이드·원본 AAC와 믹싱                                        |
| MP3  | MP3                   | 가져오기·디코딩·1080p 믹싱 출력                                         |
| WebM | VP8/Opus, VP9/Opus    | 컨테이너·디코더 검사·가져오기 경로, VP9 출력                            |

| 출력 | 인코더·muxer                                             | 검증 해상도                                                                                     |
| ---- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| MP4  | 브라우저 H.264 + 네이티브 또는 WASM AAC / Mediabunny MP4 | 1280×720, 720×1280, 1920×1080, 1080×1920; 배포본 AAC 미지원 주입 시 1280×720·720×1280 대체 출력 |
| WebM | 브라우저 VP9 + Opus / Mediabunny WebM                    | 1280×720, 720×1280                                                                              |
| MP3  | 별도 LAME WASM 인코더 / Mediabunny MP3                   | 48kHz · 스테레오 · 192kbps                                                                      |
| WAV  | PCM s16 / Mediabunny WAVE                                | 48kHz · 스테레오                                                                                |

MP4와 WebM은 해상도·FPS·비트레이트 설정을 전달해 실행 환경의 인코더를 확인합니다. VP9이 불가능하면 VP8을 검사합니다. VP8 출력 대체 경로는 코드에 있으며 모든 브라우저에서 검증한 것은 아닙니다. 오디오 전용 출력은 영상 레이어를 포함하지 않습니다.

편집 전에 보관함에서 현재 화면 크기/FPS의 출력 지원을 안내합니다. AAC 인코더가 없는 환경에서는 `@mediabunny/aac-encoder`를 기기 안에서 지연 로딩합니다. **H.264 영상 인코더 자체가 없는 환경의 MP4 대체 인코더는 제공하지 않으며**, WebM 또는 H.264를 제공하는 다른 브라우저/OS를 안내합니다. MP3·AAC 모듈의 실패는 해당 형식에만 반영하며 PCM WAV 출력은 이 모듈을 불러오지 않습니다. 출력 화면에서 바꾼 비율·해상도·FPS는 **이번 출력 스냅샷에만 적용**되고 편집 프로젝트는 유지됩니다. 전체/I/O 구간, 현재 설정의 최대 길이·예상 크기, 누락 원본·빈 화면·중첩·큰 텍스트를 확인합니다. 텍스트 잘림 검사는 근사치입니다. 결과 플레이어는 실제 비율에 맞추며 확대할 수 있습니다.

MOV·MKV·M4A·FLAC·Ogg 및 HEVC·AV1은 demuxer/브라우저 디코더가 실제로 수용하는 파일에 한해 분석 후 가져올 수 있지만, 대표 파일/OS를 포괄하는 지원 검증은 완료하지 않았습니다. AVI 변환 경로는 없습니다. 실패 시 H.264/AAC MP4 또는 PCM WAV 변환을 안내하고 기존 편집은 보존합니다. GIF는 첫 프레임의 정지 이미지로 처리합니다. WebP·AVIF·EXIF 회전은 브라우저 이미지 디코더 경로이며 별도 테스트 매트릭스는 미완료입니다. HEVC·AV1·4K 출력 선택지는 제공하지 않습니다.

검증 환경, 수치와 제한은 [docs/VERIFICATION.md](docs/VERIFICATION.md)를 확인하세요. 테스트하지 않은 브라우저·OS·코덱을 지원 완료로 간주하지 않습니다.

## 시간·전환·리플 규칙

- 모델 시간은 정수 마이크로초입니다. 출력 프레임 시각은 프레임 번호/FPS로 직접 계산하고 소수점 덧셈을 누적하지 않습니다. 미리보기 탐색은 출력 프레임 격자에 맞추고 원본은 해당 타임스탬프에서 표시될 프레임을 사용합니다. 원본의 영상·오디오 시작 시각 차이를 유지합니다.
- 시각 트랙은 화면의 위쪽이 최상위 레이어입니다. 같은 트랙의 겹친 클립은 시작 시간이 늦은 클립을 위에 그립니다. 트랙 숨김과 오디오 음소거는 출력에도 적용됩니다.
- 일반 삭제는 빈 공간을 유지합니다. 리플 삭제는 선택한 시간 구간의 합집합을 **전체 트랙에서** 제거합니다. 겹친 비선택 클립이나 영향을 받는 잠긴 트랙이 있으면 전체 작업을 거절합니다. 링크된 원본 오디오도 이동·분할·트리밍·삭제됩니다.
- 전환은 같은 시각 트랙의 빈틈 없는 접점에 적용하며 전체 길이를 바꾸지 않습니다. 디졸브는 접점 직전 설정 길이에 다음 클립의 잘라낸 원본 앞부분을 겹칩니다. 원본 여유 및 양쪽 클립 길이의 절반으로 제한합니다.
- 검정·흰색 전환은 접점 전후 각각 설정한 길이만큼 페이드합니다. 시각 전환이며 오디오는 별도의 페이드 속성으로 조절합니다. 이동·트리밍으로 접점이 끊어지면 전환을 제거합니다.
- 영상 출력 끝은 다음 출력 프레임 경계까지 반올림합니다. AAC·Opus·MP3는 인코더의 프레임 패딩 때문에 컨테이너 길이가 수 ms~수십 ms 더 길 수 있습니다. WAV는 실제 타임라인 샘플 길이입니다.

## 저장·개인정보

프로젝트 메타데이터는 IndexedDB에 변경 후 700ms 지연을 두고 자동 저장합니다. 새 프로젝트·JSON 열기·최근 프로젝트는 현재 작업 저장을 완료한 후 전환합니다. 실패하면 현재 편집을 유지하고, 성공하면 실행 취소·복사 버퍼를 초기화합니다. 가져오기와 음량/정지 프레임 작업은 전환 시 취소하며 다른 프로젝트에 결과를 넣지 않습니다. 최근 프로젝트를 복구하며 메뉴에서 저장된 프로젝트 목록·복제·복구 지점·저장소 사용량을 확인합니다. 데이터베이스 v1→v2는 기존 최근 프로젝트와 원본을 유지합니다. 다른 탭이 업그레이드를 막으면 탭을 닫고 새로고침하도록 안내합니다. '사용하지 않는 원본 정리'는 저장된 모든 프로젝트의 참조를 보호합니다. 프로젝트 JSON은 버전, 트랙, 클립, 원본 참조, 텍스트·효과를 포함하며 **원본 미디어를 포함하지 않습니다**.

기본 체크된 '가져온 원본도 기기에 저장'을 사용하면 **파일당 2GiB 이하** 파일을 별도의 IndexedDB 저장소에 보관합니다. 이는 가져오기 자체의 용량 제한이 아니라 원본 자동 보관의 상한입니다. 실제 브라우저 저장소의 여유도 검사하며 트랜잭션 실패를 성공으로 표시하지 않습니다. 큰 파일·저장 해제·권한/데이터 상실 시 원본 이름·크기·분석된 길이가 같은 파일을 다시 가져와 재연결합니다. 현재는 전체 파일 해시 검증은 없으므로 같은 이름·크기·길이의 다른 원본을 선택하지 마세요.

미디어는 Blob/파일 참조로 Worker에 전달합니다. 서버 업로드, 분석 서버, 협업, 계정, 추적 SDK는 없습니다. 앱 JS·폰트·인코더 모듈은 호스트에서 다운로드됩니다. 배포본의 폰트는 자체 호스팅합니다. 시크릿 모드, 사이트 데이터 삭제와 브라우저 저장소 축출은 영구 보관이 아니므로 프로젝트 JSON과 원본을 별도로 보관하세요.

## 구조·성능

```
src/model.ts          정수 시간, 순수 편집 함수, 합성 레이어 규칙, 직렬화 검사
src/history.ts        80단계 undo/redo, 드래그 한 번 = 한 commit
src/media.ts          Blob 기반 demux, 제한된 프레임 커서, PCM 블록 믹싱
src/render.ts         미리보기·출력 공통 Canvas 합성기
src/fonts.ts          실제 텍스트에 필요한 자체 호스팅 한글 폰트 로딩
src/engine.worker.ts  비동기 파일 분석, 썸네일/파형, 프레임 출력, 인코딩/mux
src/audio-preview.ts  Web Audio Gain + 로컬 미디어 재생
src/storage.ts        프로젝트와 원본 분리 저장, 복구·다운로드
src/*tsx              UI, 타임라인, 속성, 출력
```

렌더링·인코딩은 전용 Worker를 사용합니다. 출력은 `CanvasSource.add(timestamp, duration)`를 기다려 backpressure를 적용합니다. MediaRecorder 실시간 화면 녹화에 의존하지 않습니다. 원본 비디오는 전체 디코딩하지 않으며 각 커서는 3개 캔버스의 순환 풀과 디코더의 소량 선행 프레임만 유지합니다. PCM은 48kHz 블록으로 합성·리샘플링하고 출력하며 전체 곡을 PCM 버퍼에 올리지 않습니다. 입력 캐시는 12개 리소스이며 활성 디코딩 입력을 pin하여 사용 중인 원본이 축출되지 않게 합니다. 타임라인 클립은 보이는 시간 범위에만 렌더합니다. 빠른 탐색에서는 오래된 비동기 프레임을 버리고 최신 요청을 합칩니다.

분석 Worker는 동시에 최대 2개, 파형 작업은 최대 1개로 제한하고 파일 분석·출력 호환성 검사를 우선합니다. 파형은 120개 피크만 보관하며 분석에 시간 제한을 둡니다. 한글 폰트는 실제 텍스트에 필요한 400/700 두 굵기의 유니코드 서브셋만 로드합니다. MP3/AAC 트리밍은 디코더의 선행 구간을 읽어 오디오 프레임 경계의 누락을 줄입니다. 패널 구분선은 드래그와 방향키로 조절할 수 있습니다.

원본 한 파일과 프로젝트 타임라인은 각각 **60분**까지 지원합니다. 편집 commit·저장·열기에 공통 타임라인 제한을 적용합니다. 단일 출력 상한은 **최대 30분·예상/실제 출력 1GiB 미만·최대 한 변 1920px**입니다. UI와 Worker가 같은 길이·용량 계산을 사용하며 인코딩 중 실제 패킷 용량과 마지막 컨테이너 크기도 검사합니다. 오디오 비트레이트·프레임 반올림·컨테이너 여유를 포함해 현재 설정의 최대 길이를 표시합니다. 예를 들어 8Mbps는 약 17분 28초, 16Mbps는 약 8분 50초가 최대입니다. WAV/MP3도 30분 상한을 공유하며 **전체 믹스 피크 검사·정규화의 5분 제한은 별도**입니다.

출력 BufferTarget은 압축 결과를 메모리에 보관합니다. 한도 확대는 모든 기기에서 1GiB 출력·2GiB 원본 보관의 성공을 보장하지 않습니다. 4K·OPFS 스트리밍 출력·저해상도 프록시는 다음 단계입니다. 대용량 입력 전체를 PCM/프레임 배열로 읽지는 않지만 파일 분석·원본 IndexedDB 보관에는 브라우저 메모리/저장소 비용이 있습니다. 중간 사양 PC의 대규모 프로젝트 벤치마크는 아직 없습니다.

태블릿·모바일은 미디어/미리보기/속성 탭과 아래 타임라인을 사용합니다. 터치 트리밍, 속성 숫자 조절, 파일 선택·출력이 가능하며 모바일 OS의 WebCodecs 범위에 따라 출력 형식이 달라집니다. 휴대폰에서 데스크톱과 동일한 긴 프로젝트·4K 성능을 보장하지 않습니다.

## 배포

`vercel.json`에 Vite 빌드/`dist` 출력을 지정했습니다. 사용자 지정 Vercel 프로젝트 `cutandcut`에 연결합니다.

```sh
npx vercel link --project cutandcut --scope wondaes-projects-fe5c826b
npx vercel deploy --prod
```

계정·API 토큰은 코드에 넣지 않습니다. `.env*`, `.vercel`, 원본 미디어, 테스트 결과는 커밋/배포에서 제외됩니다. 네이티브 WebCodecs와 단일 인코더 WASM을 사용하며 SharedArrayBuffer 기반 멀티스레드 ffmpeg를 사용하지 않으므로 COOP/COEP를 필요로 하지 않습니다.

## 남은 확장

기본 색 보정·키프레임·실제 저해상도 프록시, 다중 비율 일괄 출력, 임의 TTF/OTF, GIF 애니메이션, 사용자 단축키, AVI/HEVC/AV1 테스트 파일·대체 변환, 서버 렌더링 선택 경로, 최근 프로젝트 삭제·OPFS 스트리밍 출력, 모바일 실기기·Safari/Firefox 검증은 후속 작업입니다. 예제나 계정·AI 기능은 현재 제공하지 않습니다.
