# PC·모바일 색상과 캔버스 배경 · 2026-10-22

## 확인한 근거

사용자는 갤럭시의 여러 브라우저에서 미리보기와 다운로드 영상 모두 푸른 기가 있다고 보고했다. 제공한 유튜브 채널 화면의 아랫줄 영상 여백은 측정 지점에서 RGB(17,24,30), (16,25,30)이었다. 윗줄의 여백은 RGB(6,11,14), (6,11,15)였다. 앱의 기존 기본 캔버스 배경 `#111820`은 RGB(17,24,32)이며, `Renderer.render`가 영상 바깥 여백을 이 색으로 채운다. 화면의 차이는 이 배경색과 매우 가깝다. 캡처만으로 각 유튜브 영상의 원본·코덱·모든 영상 내용의 색 변화를 확정하지는 않는다. 개인 채널 캡처는 저장소에 포함하지 않는다.

실제 1080×1920 MP4에서 이전 배경을 사용하면 여백이 RGB(18,24,32)로 디코딩됐다. 검정 배경으로 바꾸면 같은 위치가 RGB(0,0,0)이었다. PC·모바일 모두 같은 결과를 확인했다. 즉 기존 배경의 푸른 기가 파일에 포함되는 경로는 재현됐다. 모바일 UI만 원본에 푸른 필터를 적용하는 분기는 발견하지 않았다.

원본 재연결 검증에서는 직렬화된 메타데이터가 같으면 history가 변경을 생략해 미리보기가 계속 누락 오류를 표시하는 별도 문제도 재현했다. 원본 가용성의 별도 revision을 Preview에 전달하여 갱신한다. 이 신호는 프로젝트와 undo 기록에 넣지 않는다.

## 실제 파일과 일치 검사

Windows Chrome 155에서 동일한 SDR H.264 색상표·한글 자막·반투명 PNG·회전 프로젝트로 기본 UI와 390×844 모바일 UI의 1920×1080 MP4를 각각 출력했다. 0·0.5·0.9초의 전체 디코딩 프레임 SHA-256이 모두 같았다. 세 회색 패치는 미리보기와 출력에서 각각 R=G=B였고 여섯 색상 패치, 해상도·길이·출력 색 정보가 일치했다. UI 모드 전환과 재열기는 프로젝트 데이터를 바꾸지 않았다. 이는 같은 PC의 모바일 화면 재현 검사이며 다른 기기의 하드웨어 결과를 보장하지 않는다.

1080×1920의 이전 배경 프로젝트는 임의로 변환되지 않고 RGB(17,24,32)의 미리보기를 유지했다. `검정으로` 한 번으로 배경만 바뀌며 undo/redo 후 원하는 상태를 유지했다. 실제 다운로드의 여백은 검정이고 재열기 후 클립 배열은 같았다.

- [동일 프로젝트·프레임 해시](results/color-parity-local.json)
- [PC 세로 여백 전후](results/color-letterbox-standard-local.json)
- [모바일 세로 여백 전후](results/color-letterbox-mobile-local.json)

HDR 안내 UI는 HLG/BT.2020 메타데이터를 검사 데이터에 주입해 검증한다. 이 검사는 실제 HDR 디코딩이나 HDR→SDR 색 정확도 검증이 아니다. 실제 갤럭시의 SDR/HDR 원본·기기별 인코더·삼성 인터넷·디스플레이 모드·유튜브 재인코딩 차이는 미검증이다. 영상 내용 자체의 색 변화는 같은 원본과 문제가 있는 출력 파일을 확보해 별도로 비교해야 한다. 업로드된 유튜브 영상은 앱의 배경 변경으로 자동 수정되지 않으므로 프로젝트에서 다시 출력해야 한다.
