시각 트랙 간 이동은 목적지의 기존 클립을 밀거나 자르지 않는다. 위쪽 시각 트랙이 먼저 보인다. 영상·오디오를 함께 선택해도 잡은 영상 행만 시각 트랙으로 옮기고 연결 오디오는 원래 오디오 트랙에 남는다. 여러 시각 행을 동시에 선택하여 한 행으로 합치거나, 잠긴 트랙·서로 다른 종류의 트랙에 드롭하면 전체 조작을 취소하고 이유를 알린다. linked/group에 잠긴 트랙이 있으면 기존 원자적 거절을 유지한다.

네이티브 터치 검수에서 하단에 보이는 클립을 위로 끌 때 아래쪽 가장자리 자동 스크롤이 먼저 작동하여 목적지 행을 바꾸는 문제도 재현했다. 세로 자동 스크롤은 가장자리뿐 아니라 최근 포인터 이동 방향을 검사하고, 트리밍 중에는 실행하지 않는다. 트랙 바깥 드롭은 시간 변경까지 취소한다. Alt로 스냅을 잠시 끄면 이전 스냅 안내선도 제거한다.

출력 제한은 `src/export-policy.ts`, 원본 자동 보관 제한은 `src/storage.ts`에 있다. 제한 확대는 디코더/인코더 지원을 추가하지 않으며 출력 선택은 여전히 기기의 실제 인코더 검사에 따른다. 압축 패킷 용량을 인코딩 중 검사하여 예상보다 큰 출력을 조기에 중단하며 최종 컨테이너 크기도 검사한다. 예측·실제 용량 오류는 프로젝트를 보존하며 재시도는 새 Worker를 사용한다.

최종 저장 경로 검토에서 재연결은 가져오기의 크기/quota 사전 검사를 우회하던 차이를 발견했다. 두 경로가 `saveOriginal`을 공유하여 2GiB·실제 저장소 여유·transaction complete 정책을 동일하게 적용한다. 원본 PNG 정지 프레임 생성 등 별도의 내부 저장 API는 유지한다. 초과 원본과 낮은 quota는 DB 쓰기를 시작하기 전에 검사하며 저장 실패 후에도 현재 편집용 파일 참조를 유지한다.

원본 60분·프로젝트 타임라인 60분·피크 검사/정규화 5분·JSON 20MB·자막 2MB 제한은 서로 다른 목적의 기존 제한이다. 이번 요청에서 원본 자동 저장과 파일 출력의 용량/길이만 확대했다. 30분 영상이나 1GiB 출력·2GiB 저장의 모든 기기 성공을 보장하지 않는다. 출력 BufferTarget의 압축 결과 메모리 보관, OPFS 스트리밍 부재, 실기기 대용량 벤치마크 미완료는 유지한다.

측정하지 않은 데이터 조회·렌더링을 추측으로 최적화하거나 App/Timeline을 분할하기 위한 분할은 하지 않았다. 장시간 출력 스트리밍과 프록시는 별도 설계·통합 검증이 필요한 후속 작업이다. 실제 검사 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다.
