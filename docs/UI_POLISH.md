## 실제 흐름과 화면 근거

검토 중 캡처한 원본 화면은 `artifacts/polish/`에 있다. 테스트 미디어만 사용했으며 원본 파일/이미지/실행 결과는 커밋하지 않는다. 아래 그림은 같은 경로의 실제 화면이며 생성한 시안이 아니다. 모바일 전후는 모두 390×844px지만 선택 패널/미디어 상태는 다르므로 헤더 개선 근거로 비교하고 픽셀 일치 비교로 사용하지 않는다.

## 검토 범위와 유지한 항목

- 시각적 계층/버튼 우선순위/다음 행동: 선택 미디어 추가와 출력/다운로드를 우선했다. 가져오기와 배치를 구분하는 안내는 유지한다.
- 여백/정렬/긴 콘텐츠/작은 화면: 헤더, 요약, 완료 화면, 긴 파일명, 짧은 세로 빈 캔버스를 검사했다. 빈 캔버스가 좁을 때 보조 문구를 줄이며 실제 영상 비율은 바꾸지 않는다.
- 클릭 가능성/hover/active/focus/키보드: 원래 아이콘·네이티브 컨트롤을 유지하고 선택 표시·메뉴·대화상자 경계를 통일했다. IME/입력 보호를 유지한다.
- 애니메이션: 새 전환·장식 애니메이션을 추가하지 않았다. 기존 작업 로더와 `prefers-reduced-motion` 경로를 유지했다.
- 로딩/완료/오류/빈 화면: 실제 처리 상태를 구분하고 가능한 다음 행동을 안내한다. 진행률을 가짜로 보정하거나 저장 성공을 미리 표시하지 않는다.
- 동일 행동: 기존 미디어 삽입 함수를 중앙/보관함에서 공유하고 두 메뉴의 탐색/닫기를 공유한다. 엔진·model·render·storage·출력 예산/코덱·미디어 업로드 정책은 변경하지 않는다.

기본 색·레이아웃 교체, 트랙 높이/시간-픽셀 계산 변경, 자막 편집기 재설계, 새로운 효과/프록시 등은 제외했다. 이 변경은 판단과 복구 동선을 단축하는 UI 패스이며 대규모 프로젝트 성능 개선으로 주장하지 않는다. 키보드와 DOM 상태를 검사했지만 스크린리더 실기기, 모바일 OS, Safari/Firefox, 200% 확대 전 범위는 미검증이다.

최종 실행·배포 결과는 [VERIFICATION.md](VERIFICATION.md)에 별도로 기록한다.
