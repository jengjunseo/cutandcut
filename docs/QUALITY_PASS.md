# 통합 품질 개선 · 2026-10-03

사용자가 제공한 두 번째 정적 감사와 통합 품질 개선 지침을 기준으로 실행 경로를 읽고 실패 조건을 검증했다. UI·순수 모델·공통 합성기·Worker·IndexedDB 구조를 유지했으며 새 미디어 의존성은 추가하지 않았다.

| 우선 문제 | 수정 |
|---|---|
| 편집은 60분을 넘을 수 있지만 복구는 거절 | 공통 `projectLimitError`를 UI commit·읽기에 적용하고 저장은 검증 후 수행한다. 원본 파일은 60분 상한을 가져오기 전에 분석해 안내한다. 시작·길이 숫자 입력은 출력의 5분 상한 대신 프로젝트 60분을 사용한다. 거절된 숫자는 실제 값으로 돌아간다. |
| 가져오는 도중 다른 프로젝트로 결과 유입 | 시작 프로젝트 ID와 AbortSignal을 확인한다. 전환은 분석·파형·음량·정지 프레임을 취소한다. 원본 저장을 기다린 이후에도 ID를 다시 확인한다. |
| 전환 직전 편집 유실·프로젝트 간 undo | 새 프로젝트·JSON·최근 목록·복제의 공통 전환 절차가 현재 저장을 완료하고 대상도 저장한 후 교체한다. 실패 시 현재 프로젝트를 유지한다. 전환 중 입력/중복 클릭을 막고 성공 시 undo·선택·복사 버퍼를 초기화한다. 복구 지점 저장은 현재 최근 프로젝트를 바꾸지 않는다. |
| MP3/AAC 실패가 WAV 등 다른 출력까지 차단 | `codecs.ts`가 형식별 실패를 수집한다. 실제 출력 Worker는 선택 형식만 검사하고 WAV는 MP3/AAC 모듈을 로드하지 않는다. 실패한 지원 결과는 캐시에서 제거해 다음 검사에서 재시도한다. |
| 5분과 256MiB 계산 불일치 | `export-policy.ts`를 UI와 Worker가 공유한다. 오디오 비트레이트·출력 프레임 반올림·컨테이너 여유를 계산하고 현재 최대 길이를 표시한다. 완료된 실제 파일도 256MiB를 검사한다. |
| 전체 트랙 빈 구간 제거의 영향 불명확 | 시간 범위·잘릴 클립·앞으로 이동할 클립·총 영향 개수를 확인 후 적용한다. 목록은 100개까지 표시하며 잠금 방어와 한 번의 undo를 유지한다. |
| 제목까지 자막 파일에 포함 | 텍스트 역할과 자막/선택/전체 출력 대상을 추가했다. 이전 파일의 미분류 텍스트는 명시적으로 역할을 지정하거나 전체를 선택한다. |
| 출력 설정이 편집을 즉시 변경 | 설정은 출력 스냅샷에만 적용한다. 돌아가면 편집 화면과 저장된 캔버스 크기는 유지된다. |

성능 변경은 편집 commit의 전체 JSON 비교 제거, 지원 검사에 전체 프로젝트 대신 크기/FPS 전달, 전환 시 원본 Map·미리보기 Worker 정리, 선택 형식만 인코더 로드로 제한했다. Worker 생성/메시지 실패도 큐 작업과 타이머를 해제한다. 프레임 풀·PCM 블록·타임라인 가상화는 기존 경로를 유지했다.

실측 범위는 [VERIFICATION.md](VERIFICATION.md)와 [history-performance.json](results/history-performance.json)에 기록한다. `node --experimental-strip-types scripts/benchmark-history.mjs`로 비교 벤치마크를 실행할 수 있다. 전체 앱의 무지연이나 장시간 메모리 안정성을 이 수치로 주장하지 않는다.

이번 패스는 신뢰성 개선에 집중했다. 기본 색 보정·키프레임·원본 포함 백업·프로젝트 삭제·실제 프록시는 새 모델/파일 경로와 별도 검증이 필요해 추가하지 않았다. H.264 소프트웨어 인코더도 추가하지 않았다. 편집 전에 실제 지원을 알리고 WebM을 제공하는 경로를 유지한다. 모바일 OS 실기기·Safari/Firefox·대규모 편집·일반 촬영본 청취/정밀 동기화 검증은 남아 있다.
