# 화면을 유지하는 안정성 패스 · 2026-10-22

첨부 지시서의 추정을 실제 코드로 확인했다. 사용자의 이번 요청인 UX/UI 유지를 우선한다. 빠른 모드·모바일 제안·프리셋·무음 제거·새 진단 버튼·PWA 설치/업데이트 화면은 이번 범위에 넣지 않는다. 제품 이름·자체 라이선스·자동 오류 전송은 임의로 결정하지 않는다. 원본 자동 업로드나 새 의존성을 추가하지 않는다.

## 먼저 확인한 사실 V1–V10

| 항목 | 확인 결과와 판단 |
| --- | --- |
| V1 | 초기 화면은 인코더 지원을 실제로 검사하며 MP3 모듈을 불러온다. WASM은 별도 파일이 아니라 인코더 JS에 포함된다. AAC는 네이티브 인코더가 없을 때 로드된다. 폰트는 전체 파일이 아니라 CSS unicode-range에 맞는 부분과 Worker의 텍스트 부분을 사용한다. 초기 인코더가 전혀 로드되지 않는다는 가정은 틀렸다. |
| V2 | `VideoCursor`의 Mediabunny `CanvasSink`는 컨테이너의 회전/반전을 적용한다. 4K 입력을 프로젝트 크기로 축소하지만 원본 디코더는 원래 크기의 프레임을 사용할 수 있다. 출력은 frameTick(번호,FPS)로 원본 PTS를 선택하며 VFR→24fps 실제 파일 검사가 있다. 회전·4K·60fps 추가 검증은 합성 입력과 실제 촬영본을 구분한다. |
| V3 | 원본 metadata/image 캐시 12개, 활성 원본 pin, 비디오 커서 캔버스 3개. 이 개수는 GPU 디코딩 메모리의 바이트 상한이 아니다. 4K 모바일 메모리 안전성을 보장할 근거는 없다. |
| V4 | 모바일 UI는 명시적 설정이다. 자동 제안은 없다. 이번 요청에 따라 조작·화면 배치를 유지한다. |
| V5 | 단위 66개, 실제 브라우저 로컬 61개/운영 2개가 이전 배포에서 검증됐다. `.github` CI는 없다. |
| V6 | 보안 헤더는 있지만 명시적 장기 asset 캐시는 없다. 운영 응답의 `/assets/`도 `max-age=0, must-revalidate`였다. 파일명 해시를 가진 assets만 장기 캐시하고 HTML은 재검증해야 한다. |
| V7 | `scripts/benchmark-history.mjs`는 합성 History 비교만 측정한다. 영상 입출력 벤치마크가 아니다. |
| V8 | 정수 시간·링크/잠금/undo·출력 스냅샷·로컬 우선 규칙과 충돌 없이 작업할 수 있다. 이 규칙을 바꾸지 않는다. |
| V9 | 기존 Chrome 154/155 파일 검증 기록에 이어 별도 항목을 추가한다. 코드 확인·에뮬레이션·실기기 결과를 섞지 않는다. |
| V10 | 실제 iPhone/Galaxy 기기와 해당 촬영본이 제공되지 않았다. 실기기 스모크·실제 HEVC/HDR 촬영본 매트릭스는 미검증이다. 테스트 파일을 직접 만들어 이를 실제 촬영본이라고 기록하지 않는다. |

## 확인한 안정성 우선순위

1. 미리보기 렌더링 실패가 while 루프 밖으로 빠져나가면 이미 큐에 있는 최신 요청을 처리하지 않는다. 추가 조작이 없으면 이전 오류에서 멈출 수 있다. 오류에도 요청 seq를 붙여 최신 요청과 구분해야 한다.
2. 내보내기에는 취소가 있지만 Worker 무응답·메시지 역직렬화 실패에 대한 즉시 정리/비진행 시간 제한이 없다. 기존 오류/재시도 화면으로 복구한다.
3. 실패 원인의 문자열에 의존하는 부분을 좁히고, Worker가 전달할 수 있는 오류 코드와 개인정보를 제외한 진단 필드를 정한다. 새 화면이나 자동 전송은 추가하지 않는다.
4. 번들·초기 요청 측정과 +10% 예산을 도입해 이후 크기 회귀를 CI에서 막는다. 기존 출력 지원 안내를 유지하므로 초기 MP3 검사를 임의로 생략하지 않는다.

새 출력 기능·무거운 변환 엔진·편집 규칙 변경은 포함하지 않는다. T1/T3의 실기기, T4/T5/T6/T8의 UX 변화, T9 복사 버튼은 완료로 표시하지 않는다. 전체 지시서의 제품 로드맵 완료와 이번 안정성 패스 완료는 다르다.

## 수정한 문제·영향·위험

| 현재 코드에서 확인한 문제 | 실제 영향 | 적용한 변경 | 위험과 검증 |
| --- | --- | --- | --- |
| `engine.worker.ts` preview의 catch가 while 밖에 있음 | 앞 요청 디코딩 실패 시 뒤에 대기 중인 최신 요청도 멈춤 | 요청별 catch, 오류 seq, 실패 renderer 정리 뒤 최신 요청 계속 처리 | 중간. 실제 AVC 파일의 첫 요청 실패/다음 요청 성공을 수정 전에 실패, 수정 후 통과시켰다. 출력·합성 계산은 유지 |
| `Preview.tsx`가 오류 seq를 확인하지 않음 | 지난 요청의 오류가 새 탐색에 표시될 수 있음 | 최신 seq의 오류만 표시 | 낮음. bitmap 해제·현재 재생 프레임 정책 유지 |
| `render.ts` close 중 한 cursor 오류가 나면 나머지 정리 중단 | pin/decoder가 남아 다음 장면의 캐시 입장이 막힐 수 있음 | 각 cursor 정리 실패와 관계없이 pin 해제/삭제, 나머지도 정리, 캔버스는 finally 축소 | 낮음. 첫 cursor 실패에도 다음 cursor·모든 pin·canvas 정리를 단위 검사 |
| export는 Worker가 응답하지 않으면 취소 전까지 계속 실행 상태 | 출력 중 무한 대기로 오인, 재시도 진입 어려움 | 120초 동안 stage/완료량이 변하지 않으면 Worker 종료, 기존 오류/재시도 흐름 사용 | 중간. 전체 출력 시간 제한은 아님. 실제 진척이 있으면 연장하고 동일 진척 반복은 연장하지 않음. 극도로 느린 작업은 재시도/출력 구간 축소가 필요 |
| 분석/출력 Worker `messageerror` 정리 누락 | 역직렬화 실패 시 큐 슬롯이나 출력 상태가 timeout까지 남음 | 분석 큐 finish와 출력 stopWorker로 정리, 편집 보존 안내 | 낮음. 실패 handler 주입 뒤 다음 실제 분석·실제 WAV 다운로드를 검사 |
| Worker 오류가 문자열만 전달됨 | 실패 종류를 안정적으로 구분하기 어려움 | 기존 메시지는 유지하고 제한된 오류 코드/진단 allowlist 추가 | 낮음. 파일명·프로젝트명/ID·자막·원본·임의 metadata 제외, unknown은 임의 추측 없이 UNKNOWN. 클립보드·전송 UI/추적 없음 |
| 빌드 크기와 초기 전송의 구분/예산이 없음 | 무거운 변경을 수치 없이 배포할 위험 | build gzip 검사, 초기 요청 관찰, opt-in 영상 하네스, CI | 낮음. 실제 wire 미확인 값·JS heap 범위를 명시. 실행하지 않은 영상 시나리오는 미측정으로 남김 |
| 파일명 해시가 있는 asset에 명시적 장기 캐시 없음 | 재방문 때 이미 받은 불변 파일을 다시 재검증 | `/assets/`만 1년 immutable, HTML 재검증 유지 | 낮음. 서비스 워커나 offline 캐시, 저장 schema 변경 없음. 운영 헤더 별도 확인 |

`model.ts`, 편집/잠금/링크/리플 규칙, 원본 저장 정책, JSX·CSS·메뉴·버튼·키보드 체계·기본값은 바꾸지 않았다. React 변경은 기존 effect 안의 오류 처리와 timer ref 수명 관리뿐이다. 성공/취소/실패/모달 해제에서 timer와 Worker를 함께 종료하고 generation으로 지난 결과를 무시한다. 원본/미디어 버퍼를 진단에 넣거나 네트워크로 보내지 않는다.

## 휴대전화 호환성 매트릭스: 미검증을 정상으로 표시하지 않음

| 출처/조건 | 가져오기→분할→MP4→재생/저장 | 이번 근거 |
| --- | --- | --- |
| iPhone 실제 HEVC/H.264, HDR 켬/끔, 세로 1080p30/60, 4K30/60 | 미검증 | 실기기와 촬영본 없음 |
| iPhone 슬로모션/VFR·시네마틱 | 미검증 | 실기기와 촬영본 없음 |
| Galaxy 실제 HEVC/H.264, HDR 켬/끔, 세로/60fps/4K | 미검증 | 실기기와 촬영본 없음 |
| 실제 휴대전화 화면 녹화·메신저 압축본 | 미검증 | 해당 원본 없음 |
| Windows Chrome 155 합성 SDR H.264/AAC 4K60·컨테이너 회전 90° | 실제 파일 경로 통과 | 2초 입력, 링크 동시 분할, 원본 저장/재열기, 1080×1920·30FPS MP4 다운로드·별도 디코딩, 네 영역 색·프레임 PTS·오디오 에너지 |
| Windows Chrome 합성 VFR AVC → 24FPS | 기존 자동 회귀 | 원본 PTS별 색과 출력 프레임 격자 검사 |
| Windows Chrome 모바일 화면/터치 에뮬레이션 | 기존 자동 회귀 | 실제 Galaxy/Safari의 디코더·다운로드·발열을 검증한 결과가 아님 |

HDR 원본은 기존 경고와 브라우저 변환 정책을 유지한다. 공통 HDR 톤 매퍼, HEVC fallback, 4K 출력, 모바일 메모리 안전성을 새로 제공한다고 표시하지 않는다. T1/T3의 실제 기기 수용 기준은 후속 검증해야 한다. T7의 5분 가로/세로·1분 4K 시나리오는 저복잡도 합성 AVC/AAC로 초기 측정했으며 실제 촬영본이나 모바일 성능으로 일반화하지 않는다.

## 의도적으로 보류한 항목

- T3/T4/T5/T6/T8: 모바일 전환 제안·빠른 모드·프리셋·무음 제거·PWA는 화면/동작을 바꾼다. 이번 사용자의 UX/UI 유지 지시를 우선한다.
- T9: 안전한 오류 데이터 기반만 추가했다. 새 복사 버튼/설정과 자동 전송은 추가하지 않는다. 전체 T9 수용 기준 완료가 아니다. source FPS·실제 encoder 종류처럼 현재 관측하지 못하는 값은 만들어내지 않는다.
- T10: CI·버그 템플릿·첨부 파일 제외를 추가한다. 제품 이름·자체 라이선스·릴리스 태그는 임의로 선택하지 않는다. 기존 라이선스 고지는 보존한다. README 대규모 재배열·데모/샘플 UI도 이 안정성 수정에 섞지 않는다.
- 시작 시 MP3 지원 확인을 없애는 최적화는 하지 않는다. 실제 출력 가능 여부를 먼저 알리는 기존 행동을 유지하고 그 비용을 측정한다. 디코더/메모리 최적화는 실기기 병목 측정 없이 추측으로 바꾸지 않는다.
