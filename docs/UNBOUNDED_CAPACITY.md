# 고정 용량·시간 상한 제거 · 2026-11-01

요청은 기존 UX/UI를 유지하며 1GiB를 포함한 인위적인 용량·시간 상한을 없애는 것이다. 이전 문서의 1GiB/30분 출력·60분 프로젝트·2GiB 원본 보관 정책을 이 문서와 현재 README가 대체한다. 모든 기기에서 무한한 파일을 처리한다는 뜻은 아니다.

## 변경과 자원 보호

| 경로 | 변경 | 유지하는 검사 |
| --- | --- | --- |
| 가져오기·프로젝트 저장/열기 | 60분, 클립 10,000개·원본 1,000개, JSON 20MB 상한 제거 | 구조/원본 범위/링크 일관성, 정수 마이크로초 정밀도 |
| 원본 보관 | 파일당 2GiB와 임의의 20% 여유 요구 제거 | 실제 할당량 조회, IndexedDB transaction complete 확인, 실패 시 편집 유지 |
| 자막 | 2MB·10,000개·1시간 상한 제거 | 유효한 시작/끝과 정수 시간 |
| 출력 | 예상/실제 1GiB 및 30분 거절 제거 | 코덱/해상도/FPS, 원본 누락, 수치 표현 범위 |
| 파형·피크 검사 | 전체 믹스 5분 제한 및 진척 중 절대 시간 초과 제거 | 실제 진척 없는 작업의 timeout, 취소/Worker 해제 |

256MiB를 넘는 예상 출력은 지원 브라우저에서 클릭 직후 파일 저장 위치를 선택한다. 이 수치는 저장 경로의 전환 기준이다. 선택한 파일에 임시 writable로 기록하고 성공 때만 commit한다. 취소/실패는 기존 파일을 덮어쓰지 않는다. 저장 위치 선택 API가 없거나 이보다 작은 출력은 OPFS 임시 파일을 사용한다. OPFS도 없다면 기존 BufferTarget으로 대체하며 메모리 한계가 적용된다.

StreamTarget은 1MiB 청크와 backpressure를 사용한다. 영상/PCM 디코딩 캐시·동시 Worker 수는 확대하지 않았다. MP4는 fast-start의 전체 파일 메모리 보관을 끄며 컨테이너 메타데이터가 끝에 온다. 따라서 스트리밍 업로드 중 즉시 재생에는 적합하지 않을 수 있다. muxer 인덱스 등 일부 메타데이터는 여전히 파일 길이에 따라 증가한다.

WAV가 RIFF의 32-bit 크기 표현을 넘으면 RF64로 기록한다. 이 경로의 구현과 실제 4GiB 초과 파일/각 플레이어의 검증은 구분한다. 출력 해상도는 최대 한 변 1920px와 기존 FPS를 유지하며 4K 출력을 새로 지원하지 않는다.

## 임시 파일 수명

64MiB 이하 완료 결과만 제한된 바이트 복사로 반환하고 임시 파일을 즉시 정리한다. 더 큰 결과는 File로 전달하여 전체 결과를 ArrayBuffer로 읽지 않는다. OPFS 원본 파일을 삭제하면 이 File/그것을 감싼 Blob도 읽지 못하는 것을 실제 Chrome에서 확인했으므로 다운로드 직후 삭제하지 않는다.

- 생성 중 취소·실패: Worker 종료와 파일 정리를 수행한다.
- 완료 후 다운로드하지 않고 닫기: 임시 파일을 지운다.
- 다운로드 시작: 브라우저의 비동기 읽기를 위해 보관하고, 다음 출력 창 진입 때 24시간 지난 파일을 정리한다.
- Web Locks 사용 가능: 열린 결과에 잠금을 유지해 다른 탭의 정리에서 보호한다.
- 사용자 선택 파일 및 원본 보관함: 이 정리 대상에 포함되지 않는다.

실제 할당량은 원본 보관과 OPFS 출력이 공유한다. 디스크 부족/브라우저 메모리·파일 처리 오류는 고정 용량 초과와 구분해 프로젝트를 유지하며 안내한다.

## 검증

Windows Chrome에서 수행한다. 최종 실행 결과와 운영 배포 정보는 검증 종료 후 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 대용량 검사는 합성 무음 PCM의 파일 저장/길이/탐색/다운로드 경로이며 장시간 복잡한 영상의 성능 검사가 아니다.

```powershell
npm test
npx tsc --noEmit --noUnusedLocals --noUnusedParameters
npm run build
npm run check:bundle
npm run test:e2e
$env:RUN_LARGE_EXPORT='1'
npx playwright test tests/e2e/unbounded-output.spec.ts --grep '94-minute'
```

대용량 검사는 4GiB 이상의 디스크 여유를 확인하고 실행하며 결과는 무시되는 `artifacts/`에 둔다. 사용자 프로필과 분리한 일반 임시 Chrome 프로필을 생성하고 검사 후 지운다. OS 저장 대화상자 자동화를 대신해 실제 OPFS FileSystemFileHandle을 반환한다. Worker는 제품과 같은 async writable 직접 저장 경로를 사용한다. 사용자 지정 OS 경로의 실제 파일 선택 동작과 다른 OS/브라우저는 별도 실검증 대상이다.

첫 대용량 실행은 Playwright의 비공개 컨텍스트에서 실제 QuotaExceededError로 중단됐다. 앱은 저장 공간 부족을 안내하고 프로젝트를 유지했다. 조회된 할당량이나 PC의 디스크 여유만으로 실제 쓰기 성공을 보장할 수 없음을 보여 주며, 이 실패를 성공한 검사로 세지 않는다. 일반 프로필 재검증과 구분한다.

Galaxy/iPhone 실기기, Safari/Firefox, 실제 2GiB 초과 원본의 IndexedDB 저장/복구, RF64 4GiB 초과 출력, 장시간 MP4/WebM 및 다수 레이어의 최대 메모리·전력·발열은 미검증이다. 기기 성능, 저장소 할당량, 컨테이너/코덱의 실제 제약을 없애지는 않는다. 자막/JSON은 전체 텍스트 파싱이므로 매우 큰 파일은 메모리와 UI 응답성에 영향을 준다.
