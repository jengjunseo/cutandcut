# 선택형 모바일 편집 UI

## 구성과 위험 판단

기존 UI는 기본 모드로 유지하며 앱 설정의 UI 모드에서 모바일 화면을 선택한다. 프로젝트 모델·파일 저장 형식·합성·출력 엔진은 바꾸지 않는다. 기기별 UI 선택은 프로젝트 undo와 분리한다.

| 현재 문제                                     | 영향                                   | 변경                                                               | 위험 / 검사                                        |
| --------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 작은 화면에서 속성으로 이동하면 영상이 사라짐 | 구도와 자막을 확인하며 조절하기 어려움 | 미리보기·타임라인 유지, 전화에서는 하단 패널, 태블릿에서는 옆 패널 | 중간 / 비율·리사이즈·패널 전환 후 캔버스 양수 크기 |
| 200px 트랙 머리와 여러 줄 도구 모음           | 실제 클립을 보는 공간이 부족함         | 좁은 트랙 머리, 트랙 설정 패널, 고급 도구를 필요할 때 열기         | 중간 / 좌표 환산·트리밍·스냅·기존 데스크톱 검사    |
| Shift/Ctrl 없는 터치에서 다중 선택 어려움     | 그룹·다층 편집이 제한됨                | 명시적 다중 선택, 탭과 선택 클립 드래그 구분                       | 중간 / 터치 탐색·다중 이동·잠금·undo               |
| 휴대전화 키보드가 속성·완료 버튼을 가림       | 정밀 시간·한글 입력이 불편함           | 가시 뷰포트 높이, 패널 내부 스크롤, 16px 입력                      | 중간 / 축소·가로 화면·IME·숫자 입력                |
| 모든 버튼을 항상 노출                         | 행동 판단과 오작동 비용 증가           | 하단 5개 진입점, 기본 편집과 정밀 도구 분리                        | 낮음 / 기존 기능 도달성과 실제 버튼 행동           |

화면 모드는 출력 비율과 별개다. 기존 편집 모델·저장·파일 검사·출력 엔진의 규칙과 제한을 그대로 공유한다. 모드를 바꿔도 선택·클립보드·undo/redo를 보존한다. UI 선택 저장에 실패하면 실패를 안내하고 현재 편집을 유지한다.

## 실제 조작과 기능 도달성

상시 표시 영역은 프로젝트·저장·undo/redo·출력, 영상·프레임 이동·시간 입력, 타임라인·다중 선택·확대/축소와 하단 5개 진입점이다. 선택할 때만 빠른 분할·일반 삭제를 표시한다. 기존 도구를 삭제하거나 별도 모바일 편집 모델을 만들지 않는다.

| 진입점                 | 기존 기능                                                                                                                          |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 미디어                 | 보관함, 가져오기·취소·오류·재시도, 배치 선택·연속 삽입, 원본 재연결·파일 정보; 같은 패널의 전환·자막 탭                            |
| 텍스트                 | 제목·자막·박스 문구 추가; 추가 직후 속성으로 이동                                                                                  |
| 속성                   | 겹친 클립 선택, 시간·원본 범위·속도·음정 유지, 한글·폰트·스타일, 위치·크기·회전·크롭·반전, 볼륨·페이드·분리·정규화                 |
| 화면                   | 선택 해제 후 기존 프로젝트 화면비·해상도·FPS·배경                                                                                  |
| 더보기                 | 선택/분할 도구, 복사·붙여넣기·배치 방식·복제, 일반/리플 삭제, 스냅·트랙 추가, 전체 보기, 경계 이동·I/O·앞뒤 트림·빈 구간 제거·그룹 |
| 트랙 머리              | 이름, 잠금, 숨김/음소거, 단독 재생, 순서·삭제                                                                                      |
| 미리보기 설정          | 품질, 안전 영역, 크롭 핸들, 정지 프레임, 오디오 미터, 전체 화면                                                                    |
| 프로젝트 메뉴·내보내기 | 기존 최근 프로젝트·복제·복구·백업·JSON·도움말, 실제 출력 형식·구간·품질·진행·취소·결과 재생·다운로드                               |

클립 탭은 선택, **이미 선택한 클립의 드래그만 이동**으로 해석한다. 선택하지 않은 클립과 다중 선택 모드에서는 네이티브 가로·세로 탐색을 유지한다. 그룹을 이동하려면 다중 선택을 끈다. 선택한 클립의 트리밍 핸들과 숫자 속성을 함께 제공한다. 원래 마우스 박스 선택·외부 키보드도 유지하며 Ctrl/Cmd+2·4는 해당 모바일 패널을 연다. 핀치 확대를 구현했다고 표시하지 않는다. +/-와 전체 보기로 확대율을 바꾼다.

전화의 추가·속성은 **비모달 패널**이다. 전체 영상과 96px 타임라인 탐색 영역을 패널 위에 남겨 구도·재생을 확인하며 편집할 수 있다. 너비 640px 미만·높이 640px 이하의 낮은 전화에서는 패널을 여는 동안 타임라인을 접어 전체 영상과 재생 조작 공간을 확보한다. 900px 이상, 높이 600px 이상 화면은 옆 패널을 사용한다. 너비 640px 이상, 높이 540px 이하 가로 화면은 영상과 편집 영역을 나란히 배치한다. 전화에서 가시 높이가 500px 이하이면 입력 패널 우선 배치를 사용한다. 각 패널은 내부 스크롤하며 입력을 유지한 채 열고 닫는다. 더보기·트랙 설정은 모달로 포커스를 제한하고 Escape·닫기 후 포커스를 복귀한다. 시스템 화면 여백은 CSS safe-area inset으로 반영한다.

입력은 16px, 주요 버튼·숫자 입력은 44px 이상으로 제공한다. 화면이 좁거나 키보드가 열려도 패널 내용을 스크롤해 모든 속성에 접근한다. 시안·중립 배경은 기존 디자인을 유지한다. 새 장식 애니메이션·의존성은 추가하지 않는다.

## 구현 경계와 검수 중 수정

- `useEditorLayout`은 기기 UI 선택과 가시 뷰포트만 관리한다. `EditorPanel`은 기존 패널을 유지하며 배치·포커스만 담당한다. `mobile.css`는 기본 스타일 뒤에서 모바일 모드에만 적용된다.
- 타임라인 좌표 환산·스냅·박스 선택·재생헤드·자동 스크롤은 같은 트랙 머리 너비를 사용한다 (기본 200px, 모바일 76px). 편집 연산·원본·출력 시간은 변경하지 않는다.
- 터치 드래그가 클릭을 만들지 않을 때 다음 탭까지 무시되던 상태를 다음 포인터 조작에서 정리했다. 네이티브 터치 이동·트림 후 undo와 다중 선택으로 검증한다.
- 입력을 끝내는 터치에서 오래된 편집 스냅샷을 사용하지 않도록 먼저 blur commit하고 그 조작에서 드래그를 시작하지 않는다. IME·리사이즈·선택 후 텍스트 보존을 검사한다.
- 붙여넣기·트랙 추가 메뉴는 모바일에서는 도구 패널의 문서 흐름으로 펼쳐 제목·스크롤에 가려지지 않게 한다. 실제 터치로 배치 방식·트랙 생성을 검사한다.
- 기본 메뉴에 UI 설정을 추가하되 기존 최근 프로젝트의 첫 포커스와 마지막 원본 정리 위치를 유지한다. 320×568에서 속성 패널을 열 때 미리보기가 44px 높이로 지나치게 축소된 점도 검수에서 확인해 낮은 전화의 패널 배치를 다시 조정했다.

## 검증 범위

최종 회귀 결과는 [VERIFICATION.md](VERIFICATION.md)에 기록한다. 자동 검사는 Windows Chrome의 터치 에뮬레이션과 CDP 네이티브 touch 이벤트다. 320×568, 390×844, 768×1024, 1024×768, 844×390 및 390×360의 키보드 축소 유사 상황을 검사한다. 실제 Android Chrome, iOS Safari, iPad, 소프트웨어 키보드, 노치·홈바, 실제 기기의 파일 선택·코덱·메모리·장시간 성능은 **미검증**이다. 데스크톱에서 검증한 코덱 경로를 모든 모바일 기기의 지원으로 확대하지 않는다.
